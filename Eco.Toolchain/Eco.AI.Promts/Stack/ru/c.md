# ТЕХНИЧЕСКИЙ СТЕК: ЯЗЫК C (ECO STANDARDS)

Этот документ определяет правила написания и форматирования кода для всех последующих файлов (`.c`, `.h`), которые будут собираться в рамках рецепта.

## 1. СТАНДАРТЫ ОФОРМЛЕНИЯ ФАЙЛОВ
- **Кодировка**: Все заголовочные файлы и файлы реализации должны быть строго в кодировке **UTF-8 с сигнатурой (BOM) / Codepage 65001**.
- **Шапки файлов (File Header)**: Каждый создаваемый файл обязан начинаться со следующего блока комментариев:
  ```cpp
  /*
   * <character encoding> Cyrillic (UTF-8 with signature) - Codepage 65001 </character encoding>
   * <summary> [Краткое описание назначения этого файла] </summary>
   * <description> [Детальное описание бизнес-логики или структуры] </description>
   * <reference> </reference>
   * <author> Copyright (c) 2026 [AUTHOR]. All rights reserved. </author>
   */
  ```

## 2. СТАНДАРТЫ ОФОРМЛЕНИЯ ФУНКЦИЙ И МЕТОДОВ
- **Документирование методов**: Каждая функция и каждый метод виртуальной таблицы (VTbl) снабжаются заголовком:
  ```cpp
  /*
   * <summary> [Что делает функция] </summary>
   * <description> [Подробности алгоритма, описание параметров и возвращаемых кодов] </description>
   */
  ```
- **Валидация указателей**: Любой метод интерфейса должен начинаться с жесткой проверки входящих данных на `NULL`:
  ```cpp
  if (me == NULL || ppv == NULL) {
      return ERR_ECO_POINTER;
  }
  ```

## 3. ДИСЦИПЛИНА ПАМЯТИ И ТИПОВ ДАННЫХ
- **Никаких стандартных типов C**: Запрещено использовать `int`, `char`, `long`, `void*`. Используйте исключительно типы Eco: `int16_t`, `char_t`, `byte_t`, `voidptr_t`.
- **Управление памятью**: Использование `malloc`, `calloc`, `free` категорически запрещено. Выделение памяти происходит только через аллокатор компонента:
  ```cpp
  pCMe->m_pIMem->pVTbl->Alloc(pCMe->m_pIMem, size);
  ```

## 4. РАБОТА С ШАБЛОНАМИ И МАКРОСАМИ
- При получении файлов-шаблонов (из секции `assembly`), ИИ обязан строго сохранять их структуру, заменяя макросы в квадратных скобках (`[PROJECT_NAME]`, `[GUID_CID_FORMATED]`, и т.д.) на реальные метаданные проекта согласно правилам **ACOM**.

## 5. ИНТЕГРАЦИЯ И ПОИСК ШАБЛОНОВ (TEMPLATE INTEGRATION)
- **Последовательность сборки**: Шаблоны конкретных файлов подключаются далее в процессе сборки системного промпта через рецепт `assembly`.
- **Правило интерпретации**: ИИ должен использовать правила кодирования, оформления заголовков и типов данных из разделов 1–3 текущего документа (`c.md`) ко **всем последующим шаблонам файлов кода**, которые переданы ниже. Каждый такой файл будет обернут в маркдаун-блок с указанием его исходного имени в комментариях.
- **Резервное правило (Fallback Rule)**: Если конкретные файлы шаблонов не представлены ниже в тексте промпта, ИИ (в роли кодера) обязан использовать в качестве эталона базовые файлы шаблонов из системной папки **`Templates/`**, выбирая подпапку и структуру в зависимости от расширения целевого файла:
  - Для **C** (`*.c`, `*.h`): папка `Templates/` (файлы `IdROOT.h`, `CROOT.h`, `CROOT.c` и т.д.).
