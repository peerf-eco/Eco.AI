=== SKILL: ECO-WIZARD SCAFFOLDING (v0.1.3+ JSON manifest contract) ===

You generate structure ONLY through the `eco_wizard` tool — never hand-write
project boilerplate (directory trees, IdEco*/IEco* skeletons, factories,
Makefiles, .code-workspace) in your response. The wrapper speaks the
deterministic JSON contract (`--json` manifest v1) against eco-wizard >= 0.1.3;
older binaries are handled by the wrapper for the legacy-compatible argument
subset; JSON-only arguments fail explicitly instead of being silently ignored.

# WHEN TO CALL
- New project / component / application scaffold → call BEFORE writing any file.
- Existing scaffold present → adapt it; do not regenerate over existing files.
  Re-generation over the same name fails with POLICY_EXISTS (exit 5) unless
  you pass if_absent=true (idempotent: re-run yields status "reused").
- Missing binary → report the actionable error once and continue with the
  plan; do NOT silently substitute hand-written templates unless the task
  explicitly demands it.

# ARGUMENT CHEAT-SHEET (tool args map 1:1 to CLI flags)
- name:        Eco-prefixed CamelCase (`Eco.List1`). Wizard adds `Eco.` if absent.
- project_type COM    → component (factory + vtbls) — DEFAULT choice
               APP    → executable application (generates EcoMain glue)
               LIB/ECOOS/LINUX/BOOT parse but are POLICY-REJECTED (exit 5):
               no complete scaffold exists for them — do not call with these.
- language:    C or CPP ONLY. The wrapper rejects Python/Java up front — for
               those, follow the task spec directly instead of calling the tool.
- options:     codes: pn (namespace postfix), cp (connection points — only if
               the plan needs them), ai/ao/co (aggregation inner/outer,
               containment outer), ut (unit-test project — include for
               components), ts (thread-safe, only when concurrency is planned).
               Do not add unused options: each widens generated surface.
- use_env_framework: keep true — resolves dependencies from $ECO_FRAMEWORK
               (the wrapper pre-checks it; an unset/missing path is an
               immediate actionable error, not a wizard run).
- entry:       base name for the entry file + identifiers (rarely needed;
               default derives from --name).
- registrations: COM registration identifiers (stored in config.json).
- target:      triplet like linux/x64/gcc_v132 — omit unless the plan pins a
               non-default OS/arch/variant.
- design_docs: keep true; false skips the localized .fodt DesignFiles.
- if_absent / if_exists: collision policy. Default in JSON mode is fail —
               a second run over the same name is an ERROR, not a refresh.
- dry_run:     plan-only probe (status "dry-run", writes nothing) — use when
               unsure what a type/option combination produces.
- verify:      keep true — the wizard runs the `make -n` build dry-run and
               fails generation on validation errors (broken scaffolds never
               reach the result).

# LAYOUT CHANGE (v0.1.3+): NESTED project_dir
The wizard scaffolds INTO '<out_dir>/<Name>/' — a NESTED directory. The tool
result states project_dir (e.g. 'Eco.Calc'), the generated file list, the
EcoMain entry file (SourceFiles/<Name>.c — named after the project, NOT
EcoMain.c), and the run_build project_subdir (e.g.
'Eco.Calc/AssemblyFiles/Linux/gcc_v132'), all already relative to project_dir.
Use those values VERBATIM; do NOT re-explore with list_dir/glob and do NOT
prefix the build subdir with the project name again.

# EXIT-CODE MEANINGS (surfaced verbatim in tool errors)
0 ok · 2 usage error (bad flag/value) · 3 not-found (ENV_NOT_SET, missing
spec) · 5 policy-denied (POLICY_EXISTS collision, unsupported type/option
combination). Errors carry a code + hint — read the hint, fix the argument,
re-invoke; do NOT retry the identical call.

# AFTER GENERATION
1. The result IS the manifest: out_dir tree, entry file, build_subdir. Zero
   exploration re-deriving them.
2. Fill generated TODOs; preserve exact factory symbol
   `GetIEcoComponentFactoryPtr_<32-hex CID>` and UGUID blocks.
3. After editing/deleting generated files (or before the first build when in
   doubt) call `eco_wizard_validate(path='<Name>')` — it checks config.json,
   required dirs, entry/build files, Makefile source references and workspace
   files, and lists error findings (MISSING_ENTRY, MAKEFILE_REF_MISSING, ...)
   so a broken scaffold fails in ONE tool call instead of a build cycle.
4. Report one concise structural summary; details stay in traces.
