## 1. Цель задачи

Подготовить готовый к заполнению `.docx`-шаблон выпускной квалификационной работы (ВКР) с:
- корректным оформлением по методическим рекомендациям НИУ ВШЭ (Times New Roman 14, поля 30/10/20/20 мм, междустрочный 1.5, нумерация страниц снизу по центру);
- титульным листом и оглавлением по образцу методички (Приложения 5–6);
- всеми главами и параграфами с заголовками первого и второго уровня (16 пт / 14 пт, полужирный);
- развёрнутыми авторскими подсказками под каждым параграфом: что писать, на что ссылаться, какие фрагменты кода из репозитория цитировать;
- предзаполненным разделом «Описание применения генеративной модели» (обязателен по методичке при использовании ИИ);
- предзаполненным библиографическим списком с реальными верифицируемыми источниками, оформленным по стилю методички.

Помимо `.docx`, требуется сохранить **копию** исходного файла-задания (`diploma/Документ Microsoft Word.docx`), чтобы заметки руководителя не были потеряны.

## 2. Контекст проекта

Скелет описывает реальный проект `H:\ai-hse-diploma-agent` — ИИ-агента для сборочного программирования платформы Eco. Этапы эволюции (V1 → V7) и архитектурные решения зафиксированы в `memory/MEMORY.md` и связанных файлах. **Финальная (продакшн) архитектура — V7: кастомный `Orchestrator` (`agent/v6/orchestrator.py`), управляющий тремя агентами-циклами pi_ai (architect / coder / tester, `agent/v6/agents/*`) поверх портированного harness'а (`agent/pi_ai/`). V7 НЕ использует ни LangGraph, ни LangChain — `langchain_openai` удалён.** Пятиузловой LangGraph-пайплайн `planner → setup → coder → tester → escalate` (`agent/v6/`) сохранён только как откатной вариант (rollback, эндпоинт `/ws/v6/chat`).

Источник содержательного плана: `diploma/Документ Microsoft Word.docx` — заметки научного руководителя с перечнем обязательных тем и порядком изложения.

- Титульный лист (Приложение 5 методички): «ФЕДЕРАЛЬНОЕ ГОСУДАРСТВЕННОЕ АВТОНОМНОЕ ОБРАЗОВАТЕЛЬНОЕ УЧРЕЖДЕНИЕ…», название темы (рус + EN), «Выпускная квалификационная работа — МАГИСТЕРСКАЯ ДИССЕРТАЦИЯ», направление 01.04.02, ОП «Искусственный интеллект и компьютерное зрение»

### 3.2. Введение  *(~3–4 стр.)*

- Цель и задачи работы
- Научная новизна и практическая значимость

### 3.3. Глава 1. Сборочное программирование как предметная область  *(~5–7 стр.)*
- **1.1.** Концепция сборочного программирования (Лаврищева Е.М., Грищенко В.Н., 2009)
- **1.2.** Industrial Software Components — М. Дуглас МакИлрой, NATO Conference 1968, эволюция идеи компонентного ПО

- **1.4.** Постановка задачи: ИИ-агент, склеивающий готовые компоненты и достраивающий недостающие (GUI и т.п.)

### 3.4. Глава 2. Теоретические основы построения ИИ-агентов  *(~10–12 стр.)*
- **2.1.** Архитектура трансформера: от «Attention Is All You Need» (Vaswani et al., 2017) до современных LLM
- **2.2.** Structured output: function calling (OpenAI 2023), JSON mode, constrained decoding
- **2.3.** Понятие ИИ-агента: ReAct (Yao et al., 2023), цикл «мысль → действие → наблюдение», tool use

- **2.6.** RAG для работы с кодом: dense retrieval vs graph-RAG (LightRAG); векторные хранилища (sqlite-vec, ChromaDB, Qdrant) и выбор встроенного sqlite-vec + FTS5

### 3.5. Глава 3. Проектирование архитектуры агента: эволюция решений  *(~10–12 стр.)*
- **3.1.** Поколения V1–V2: первичные эксперименты и их ограничения
- **3.2.** V3: жёсткий граф LangGraph с разделением ответственности по нодам
- **3.3.** Применение RAG для чтения кода: sqlite-vec + FTS5, AST-чанкер (tree-sitter-c), эмбеддинги qwen3-embedding-8b; обоснование vector-only и отказа от LightRAG для нашего кейса
- **3.4.** Выявленные проблемы: некорректный код, сбои сборки cl.exe, неверная структура папок
- **3.5.** V4: HITL — «план → апрув пользователя → разработка» через `interrupt()` LangGraph
- **3.6.** V5: трёхузловой пайплайн (Planner / Coder / Executor) с Markdown-handoff между нодами вместо `with_structured_output`
- **3.7.** V6: пятиузловой пайплайн `planner → setup → coder → tester → escalate` с отдельным агентом-тестировщиком (read-only)
- **3.8.** Принципиальное ограничение `langchain_openai` в инференсе на универсальных эндпоинтах OpenAI-compatible и переход к harness-подходу
- **3.9.** V7 (продакшн): отказ от LangGraph — кастомный `Orchestrator` поверх pi_ai-harness, три агента architect / coder / tester, инструмент `search_marketplace` (sqlite-vec RAG), эндпоинт `/ws/v7/chat`. V6 оставлен как rollback

## 7. Риски и ограничения

- **Дедлайн 2 дня.** Скелет — это каркас для заполнения, а не готовый текст. Объёма ≥ 40 страниц без содержательного наполнения студентом не достигнуть.
- **Антиплагиат ≥ 80 %.** Подсказки в скелете курсивом — их нужно стереть после заполнения, иначе они попадут в чек. В шаблоне ставлю явные маркеры `[ПОДСКАЗКА: …]`, чтобы их легко было найти и удалить целиком.
- **Цитирование собственного кода.** Делаю короткими блоками 10–20 строк с явной атрибуцией `file_path:line_number`, не дамплю файлы целиком.
- **Раздел про генеративные модели обязателен** — не забыть его не удалять при чистке.

## 8. Не делается в рамках этой задачи (YAGNI)

- Не пишется содержательный текст глав «прозой», только подсказки под каждым параграфом.
- Не строятся реальные графики/таблицы результатов (заполняет автор по своим данным).
- Не делаются скриншоты UI — указано место под них в Приложении Г.
- Не оформляется отзыв руководителя и рецензия (это документы извне).
